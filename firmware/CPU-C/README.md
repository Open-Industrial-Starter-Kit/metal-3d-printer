# CPU-C - galvo and fiber laser

CPU-C of the Control Board V2 drives the galvanometer scan head over the
**XY2-100** protocol and controls the Raycus RFL-C200A fiber laser. It is the
RP2350B with the 8 MB PSRAM populated, which buffers the scan trajectories.

The XY2-100 signalling is generated by the RP2350 **PIO** block rather than in
software, so the 2 MHz bit clock stays jitter free while the CPU prepares the
next position.

## Files

| File | Purpose |
| --- | --- |
| **[xy2_100.pio](xy2_100.pio)** | PIO programs that generate the XY2-100 frames |

### xy2_100.pio

Two state machine programs:

| Program | State machine | Role |
| --- | --- | --- |
| `xy2_100` | SM0 | master - drives the X data line and generates CLOCK and SYNC |
| `xy2_slave` | SM1 | slave - drives the Y data line in step with the master |

Both shift out a 20 bit frame, one bit per clock, with `side_set` carrying the
CLOCK and SYNC lines so the levels change in the same cycle as the data. The
frame is reloaded with a non-blocking `pull`, so when the FIFO is empty the
previous position is repeated instead of stalling the scan head.

On the board these reach the DB15 through an AM26LS31CDR quad differential line
driver, as `CLK±`, `SYNC±`, `XCH±` and `YCH±`. The head's ±15 V supply is
switched by relays K6 and K7 from `PIO_PWR_RLY`, so firmware has to close those
before the scanner responds. See **[../../pcb](../../pcb)** for the schematic.

Assemble it on its own with:

```
pioasm -o c-sdk xy2_100.pio xy2_100.pio.h
```

In a Pico SDK project it is normally generated at build time with
`pico_generate_pio_header()`.

## Status

*In preparation.* The firmware is a custom port of
[OpenGalvo](https://github.com/Dev-Fernandez/OpenGalvo), originally written for
the Teensy 4.0. Current work is testing the galvo code and bringing up the
fiber laser interface.
