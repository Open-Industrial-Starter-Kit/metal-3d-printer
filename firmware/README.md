# Firmware - OISK Metal 3D Printer

The firmware of the OISK Metal 3D Printer runs on the **Metal 3D Printer Control
Board V2**, which carries three RP2350B microcontrollers connected to each other
by serial links. Each CPU can be operated individually or as part of the
coordinated machine.

- **[Metal 3D printer firmware.pdf](Metal%203D%20printer%20firmware.pdf)** -
  firmware architecture and responsibility of each CPU

## Architecture

| CPU | Role | Responsibilities |
| --- | --- | --- |
| CPU-A | Motion | grblHAL, 5 axes (X and Y move the diode laser, Z the printing piston, A the reserve piston, B the recoater), inductive end stops, incoming G-code, diode laser power modulation |
| CPU-B | Main controller | Ethernet link to the computer, communication between the other two CPUs, oxygen / temperature / fine dust and other sensors, dispatching of a custom G-code extension, coordination of the machine |
| CPU-C | Galvo and fiber laser | XY2-100 protocol at 2 MHz generated in PIO for the galvanometer X and Y axes, power modulation and frequency of the fiber laser module, galvo G-code handling with speed and acceleration profiling - a custom port of OpenGalvo (originally running on a Teensy 4.0) |

The hardware these firmwares target is documented in **[../pcb](../pcb)**.

## Sources

| Folder | CPU | Toolchain | State |

Both trees are the firmwares of the [Piccola CNC](https://www.piccolacnc.com/) taken
as the starting point for this machine, and are being adapted to the Control
Board V2.

### CPU-A

grblHAL for the RP2350B. Build it with the Raspberry Pi Pico extension for
VS Code, or from the command line:

```
cd CPU-A/build && ninja
```

The board definition in `CPU-A/boards/pico/metal_printer_v2.h` selects the
RP2350B (`PICO_RP2350A 0`, 48 GPIO). Do not let the Pico extension rewrite
`PICO_BOARD` back to `pico2`, which is the RP2350A. Configure with
`-DADD_USB_SERIAL=ON` to drive the grblHAL stream from the CPU-A USB-C port
instead of the UART0 link to CPU-B, which is useful on the bench.

Axis pins, as wired on the Control Board V2:

| Axis | STEP | DIR | ENABLE | LIMIT |
| --- | --- | --- | --- | --- |
| X - laser head | GP17 | GP12 | GP22 | GP5 |
| Y - laser head | GP18 | GP13 | GP23 | GP6 |
| Z - build piston | GP19 | GP14 | GP24 | GP4 |
| A - reserve piston | GP20 | GP15 | GP25 | GP3 |
| B - recoater | GP21 | GP16 | GP26 | GP2 |

Door input is GP8, the Laser 1 relay GP33 and the Laser 1 PWM GP35. The step
pulses are generated by the PIO block from `STEP_PINS_BASE 17`, so the five
step pins have to stay consecutive.

### CPU-B

PlatformIO project for the Arduino-Pico core, derived from the Piccola CNC
CPU-B firmware. Build it with:

```
cd CPU-B && pio run
```

The port to this board is being done in three phases. **Phase 1 is complete**:
the firmware builds for the Control Board V2 and no longer drives any pin that
belongs to another function.

| Phase | Scope | State |
| --- | --- | --- |
| 1 | Strip to this board: no WiFi, no ESP32-C3, no hardware this machine does not have | done |
| 2 | SD card on SPI1 | pins done, untested on hardware |
| 3 | W5500 Ethernet as the network transport | not started |

#### What phase 1 changed

- Board target `rpipico2w` (RP2350A with CYW43 WiFi) to `MyRP_2350B`, a plain
  RP2350B. This board has no radio.
- Removed the ESP32-C3 driver and the WiFi, BLE and WebSocket layers that ran
  over it: about 836 lines plus the 843 line `ESP32C3Manager`.
- Removed the `Serial2` port on GP8/GP9, which is the RS-422 transceiver here,
  and the distance laser sensor port on GP4/GP5, which is the link to CPU-C.
- Moved the RGB LED to its real pins, GP31/GP32/GP33.
- Pointed the SD card at SPI1 with its own chip select, GP29. It was on GP17,
  which is the W5500 chip select on this board.
- Parked the outputs belonging to Piccola CNC hardware this machine does not
  have, among them the axis enable mirrors and the brushless motor direction,
  on pins the board leaves spare, so nothing can contend with the Ethernet,
  SPI1 or RS-485 nets that sit on their original pins.

Every pin the firmware declares has been cross-checked against the CPU-B
netlist of the schematic: 23 pins, no conflicts.

#### Naming

The firmware carries no references to the machine it came from. The sketch is
`MetalPrinter_CPUB.ino`, the default machine name is `Metal 3D Printer #1`, and
the G-code bounds metadata written into job files is tagged `;OISK_BOUNDS`.
The WiFi and BLE layer left ~70 dead constants and ~25 dead state variables
behind; those are gone, and what remained of the network naming is now neutral
(`NetworkSettings`, `INPUT_SOURCE_NETWORK`, `debuggingNetwork`) ready for the
Ethernet work.

Two JSON API changes came out of that, both for hardware that no longer exists:
the `enableESP32Passthrough`, `disableESP32Passthrough` and
`getEsp32PassthroughStatus` commands are gone, and `setDebuggingESP32` is now
`setDebuggingNetwork`.

`NetworkSettings` itself is kept even though nothing reads it at runtime. Every
EEPROM region is addressed as a running sum that starts with its size, so
removing it would move every other settings block.

#### What is still a CNC router

The JSON API, the macro engine, the serial protocol and the SD card layer are
unchanged, which is deliberate. The machine logic above them still assumes a
spindle, a tool changer, a rotary axis and probing routines that this machine
does not have. Those are untouched for now: they are inert because their pins
are parked, and removing them is a separate job from making the firmware safe
to run.

`sendJsonResponse()` is the single point where a response leaves CPU-B, and it
selects the transport from `currentInputSource`. Adding the Ethernet path in
phase 3 means adding a branch there and a receive function that mirrors the old
WebSocket one: set `currentInputSource`, deserialize into `receivedJsonBuffer`,
then call `handleJson()` or `handleRawPassthroughLine()`.

For driving grblHAL while CPU-B is still being ported, the passthrough test in
**[test/CPU-B_passthrough](test/CPU-B_passthrough)** bridges the CPU-B USB-C
port to CPU-A and touches nothing else.
